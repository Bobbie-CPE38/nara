# โครงของเอกสาร

| ข้อ | เนื้อหา |
| :-: | :-- |
| **0, 1** | สรุปงานสามคน และขอบเขต: อะไรอยู่ในรอบ 1 อะไรไม่อยู่ |
| **2** | Transition ใหม่ 5 เส้น และผลต่อ Orchestrator |
| **3** | กติกา "ผู้สมัครคนถัดไป" แทน Seam 2 เดิม |
| **4** | แถวที่แต่ละเส้นทางเขียน และลำดับ Lock |
| **5** | Audit ของเส้นทางใหม่ และลำดับที่คาดหวังของ 5 กรณี |
| **6** | คำตอบของ API ที่เปลี่ยน และหน้าเว็บที่ต้องแก้ตาม |
| **7** | Hard Rules: รหัส, interface, สิ่งที่ Safety บันทึก |
| **8** | Coverage: ความหมายของ Minimum และ Seam จาก Gap ไป Solver |
| **9, 10** | Seed Scenario, กติกาเทสต์ และลำดับ PR 0 ถึง 6 |
| **11** | ไฟล์กลางที่ต้องแก้ และใครแก้ |
| **12** | คำถาม Q1 ถึง Q20 สำหรับที่ประชุม พร้อมข้อเสนอและคนที่ถูกขวาง |
| **13** | สิ่งที่ผมยังไม่ได้ตรวจ |

---

## ข้อเสนอหลัก

- **Transition 5 เส้น:** Reject, Safety ไม่ผ่าน และไม่อนุมัติ กลับมาที่ `OUTREACH` จุดเดียว เพื่อให้กติกาเลือกคนถัดไปอยู่ที่เดียว ส่วนไม่เหลือผู้สมัครไป `MANUAL_HANDOFF` แทน `FAILED`
- **PR 0 เป็นของคุณ:** เอกสาร + `transitions.py` + เทสต์ ไม่เปลี่ยนพฤติกรรม เข้าก่อนทุกตัว

---

## จุดที่ผมเจอระหว่างร่าง ซึ่งจะพังถ้าไม่ตกลงก่อน

1. **Offer เก่าที่ `ACCEPTED`:** Seam 4 ต้องการ Offer `ACCEPTED` ของเคสหนึ่งแถวพอดี ถ้าคนแรกรับแล้วถูกปัดตก แล้วคนที่สองรับ จะมีสองแถวและ Safety รอบสอง Error ทันที ผมเสนอให้ตั้ง Offer ของคนที่ถูกปัดตกเป็น `CANCELLED`
2. **กฎ "มี Offer ค้าง" อยู่ในไฟล์ของ Solver:** การเลือกคนถัดไปของคน 3 ต้องใช้กฎเดียวกัน ถ้าไม่ย้ายเป็นของกลางจะมีกติกาสองที่ แบบที่เคยเจอในขั้นที่ 4
3. **ลำดับ Lock ตอน Safety ไม่ผ่าน:** ต้องแก้ Offer ขณะถือ Lock ของเคสอยู่ ซึ่งผิดลำดับ "Outreach ก่อนเคส" ถ้ามองตามตัวอักษร ผมวิเคราะห์ว่าปลอดภัยเพราะโค้ดอื่นล็อกเฉพาะแถว `SENT` แต่ต้องเขียนเป็นกติกาและมีเทสต์
4. **`minimum_staff` ไม่ถูกใช้เลยตอนนี้:** งานของคุณชื่อ "Role + Skill + Minimum" แต่เอกสารปัจจุบันเขียนว่าไม่ใช้ค่านี้ ต้องตัดสินก่อนว่า Minimum หมายถึงอะไร (Q18)
5. **`test_transitions.py` จะแดงทันทีที่เพิ่มเส้นใหม่:** เพราะเทสต์ยอมรับเฉพาะเส้น Golden Path ต้องแก้คู่กับ `transitions.py` ใน PR เดียว

---

## ข้อจำกัดของร่างนี้

- รายการเทสต์ที่จะแดงมาจากการอ่านโค้ด ยังไม่ได้รันจริง
- ตาราง Hard Rules เดาความหมายจากชื่อคอลัมน์ของ `HARD_CONSTRAINT_POLICY` ต้องให้คน 2 ยืนยัน
- เรื่อง Lock ยังไม่มีเทสต์พิสูจน์
